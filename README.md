# OrbitVitals AI

Explainable health monitoring for long-duration space missions, built for the
NASA Space Apps Challenge 2026.

> **Research prototype, not a medical device.** Outputs support decisions made by
> people; they are not diagnoses or treatment advice. Every crew measurement shown in
> the application is **synthetic (simulated) data**, never a real astronaut record.
> NASA does not endorse this project.

## What is delivered

| Layer | Technology | Location |
| --- | --- | --- |
| Dashboard (Crew, Medical, Assistant, Sleep plan, Nutrition, Exercise) | React 19, TypeScript, Vite | `frontend/` |
| Cognition test battery (bundled into the dashboard) | React, TypeScript | `cognition-frontend/` |
| API and scientific engines (quality, personal baselines, sleep, activity, nutrition) | Python 3.11, FastAPI | `backend/` |
| Reproducible synthetic mission seed | Python | `backend/app/demo_seed/` |
| NASA dataset evidence adapter (read-only research context) | Python | `backend/app/nasa_evidence/` |
| Assistant service | Python 3.11, FastAPI, Ollama | `ai_agent/` |
| Specialist retrieval for the reviewer | Python | `rag/` |

### Assistant

- **Primary model: Google Gemma 3 4B** (`gemma3:4b`), run locally through Ollama. It
  only drafts wording: every sentence is verified against the backend records of the
  selected crew member, and anything unsupported is rejected. Without Ollama the
  assistant answers with fixed, rule-based sentences.
- **Optional reviewer: Google MedGemma 1.5 4B** (`medgemma1.5:4b`) reviews the reading of
  a flagged result. It is not called for greetings, factual or medication questions.
- Evidence: 114 independent summaries of NASA and peer-reviewed sources, each cited
  with its link. No measurement, diagnosis or citation is generated by a model.
- English and Italian; follow-up questions use earlier turns of the **same** astronaut.
- **One persistent conversation per astronaut.** The Assistant follows the astronaut
  selected in Crew. Each question is a server-owned job (`POST /agent/v1/jobs`): it keeps
  running when the Assistant is closed, the page is changed or refreshed, or the tab
  is closed; the answer is stored and shown in the conversation of the astronaut who
  asked. Repeating a request id never runs it twice.

## Data

| Mode | Source | Used for |
| --- | --- | --- |
| Server (default, Demo mode off) | FastAPI + the synthetic seed `orbitvitals-mission-demo-v1`: 893 simulated measurements, 36 personal baselines, 13 evaluations for Astronauts A, B and C | Dashboard and Assistant, from the same stored records |
| Training scenarios (Settings → Demo mode) | The frontend's built-in deterministic synthetic scenario | Training and walkthroughs; the Assistant is paused |

**Approved scenario on FastAPI (Demo off).** `python -m app.demo_seed.approved` seeds a
fresh API with the observations of the approved frontend scenario (Astronaut A on mission
day 15: resting heart rate 65 bpm, HRV 47 ms, sleep 6.0 h), exported unchanged from the
frontend generators by `integrations/approved-demo/export_observations.mjs`: 8,055
simulated observations for days 1-15, nutrition included. Data quality, personal baselines
(mission days 1-7) and a sleep evaluation (days 8-15) are computed by the backend engines,
not copied from the interface. See [integrations/approved-demo](integrations/approved-demo/README.md)
for what matches and what remains different.

**NASA research data.** The backend contains reproducible, read-only analysis tools for
two NASA archived terrestrial analogue studies (UTMB Bedrest Campaign 1 actigraphy and
Campaign 3 MR001G tilt). They are ground studies, not in-flight astronaut records and
not flight validation. Their source files and participant-level derivatives are not
redistributed. They never replace the synthetic crew data. See
[docs/nasa-evidence-adapter.md](docs/nasa-evidence-adapter.md).

## Run it locally (Windows PowerShell)

Prerequisites: Python 3.11, Node.js 22+, [Ollama](https://ollama.com).

```powershell
# 1. Models (once)
ollama pull gemma3:4b
ollama pull medgemma1.5:4b          # optional reviewer

# 2. Backend API on :8000, then the synthetic seed
cd backend
py -3.11 -m venv .venv; .\.venv\Scripts\Activate.ps1
pip install -r requirements-dev.txt
uvicorn app.main:app --host 127.0.0.1 --port 8000
# in a second terminal, from backend/ with the venv active, ONE of:
python -m app.demo_seed.approved --base-url http://127.0.0.1:8000/api/v1   # approved scenario
python -m app.demo_seed seed --base-url http://127.0.0.1:8000/api/v1       # alternate seed

# 3. Assistant service on :8100
cd ai_agent
py -3.11 -m venv .venv; .\.venv\Scripts\Activate.ps1
pip install -r requirements-dev.txt
$env:ORBITVITALS_AGENT_BACKEND_BASE_URL = "http://127.0.0.1:8000/api/v1"
$env:ORBITVITALS_AGENT_SPECIALIST = "medgemma"   # or "none"
uvicorn orbit_agent.api:app --host 127.0.0.1 --port 8100

# 4. Dashboard on :5173 (proxies /api to :8000 and /agent to :8100)
cd frontend
npm ci
# with the approved scenario: its mission clock and day 1
$env:VITE_AS_OF = "2026-11-14T10:40:00Z"; $env:VITE_MISSION_START = "2026-10-31"
npm run dev
```

Open `http://localhost:5173`. `GET http://127.0.0.1:8100/agent/v1/health` reports the
backend, Gemma and MedGemma availability. Other ports: set `VITE_BACKEND_ORIGIN` and
`VITE_AGENT_ORIGIN` before `npm run dev`.

## Tests

```powershell
cd backend;  python -m pytest          # API, engines, seed, NASA history audit
cd ai_agent; python -m pytest          # assistant, offline (no model needed)
cd frontend; npx tsc -b; npx vitest run; npx vite build
```

## Known limitations

- With the approved scenario on FastAPI, every plotted daily value and nutrition total
  matches Demo mode; backend-computed quality flags, some usual ranges and demo-only
  workflow items (review events, device-offline scenario, sleep-aid plan) still differ.
  Details in [integrations/approved-demo](integrations/approved-demo/README.md).
- Vital-sign evaluations are not computed by the backend, so the Assistant reports the
  stored heart-rate readings' quality but no vital-sign status.
- The Assistant answers from the latest stored results; it is paused for past mission
  days and in Demo mode.
- MR001G source units and dataset-specific redistribution terms remain unresolved.
- No clinical or flight validation has been established.
